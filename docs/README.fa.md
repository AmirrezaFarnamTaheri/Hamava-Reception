# مستندات هم‌آوا

[English](README.md) · [صفحهٔ اصلی پروژه](../README.fa.md)

**از کاری که می‌خواهید انجام دهید شروع کنید.** این راهنماها برای نسخهٔ **0.2.2** کد هم‌آوا نوشته شده‌اند. هر راهنمای اصلی یک نسخهٔ فارسی و یک نسخهٔ انگلیسی دارد که ابتدای صفحه به هم پیوند داده شده‌اند.

## ارتباط راهنماها با هم

**بیمار نوبت می‌خواهد.** راهنمای محصول تجربهٔ بیمار را توضیح می‌دهد؛ راهنمای API فراخوانی‌ها را نشان می‌دهد؛ معماری روشن می‌کند چرا زمان‌بند پیش از ثبت نهایی دوباره ظرفیت را می‌سنجد. عملیات می‌گوید اگر نتیجه نامعلوم ماند، کارکنان چه کنند. استقرار هم روش حفظ سرویس و بازیابی پس از خرابی را توضیح می‌دهد.

**مرکز می‌خواهد تماس تلفنی فعال کند.** ابتدا مجوز و آزمون کنترل‌شده را در [اتصال سرویس‌ها](provider-integrations.fa.md) بخوانید. [معماری](architecture.fa.md) معنی اتصال واقعی کارکنان را توضیح می‌دهد. [استقرار](deployment.fa.md) شبکهٔ خصوصی و [تأیید مرکز](clinic-acceptance.fa.md) پنج آزمون عملیاتی را پوشش می‌دهند. سنجش گفتار در [پژوهش](research.fa.md) آمده است.

**توسعه‌دهنده برنامه را تغییر می‌دهد.** در راهنمای توسعه فایل‌های مرتبط را پیدا کنید، آزمون رگرسیون بنویسید و با کمک API/معماری قرارداد را حفظ کنید. سپس هر دو نسخهٔ زبانی راهنمای مرتبط را به‌روزرسانی کنید.

## مرجع معتبر کدام است؟

برای رفتار پیاده‌شده به کد، آزمون و `/openapi.json` سرور در حال اجرا مراجعه کنید. نتیجهٔ آزمون هر بازنگری در اجرای GitHub Actions و فایل‌های پیوست همان اجراست. آمادگی واقعی از سوابق پذیرش مرکز، رسید تأمین‌کننده و مشاهدهٔ محیط عملیاتی روشن می‌شود. این راهنما روش انجام کار را شرح می‌دهد و جای آن شواهد را نمی‌گیرد.

[فهرست نیازمندی‌ها](requirements-register.fa.md) تصویری از نسخهٔ **0.2.0** است، نه داشبورد پیشرفت امروز. بخشی از مسیرهای مدارک در JSON به فایل‌هایی اشاره دارند که پس از پاکسازی، فقط در تاریخچهٔ Git حفظ شده‌اند؛ نباید آن‌ها را فایل فعال یا نتیجهٔ آزمون امروز تصور کرد.

## برای یک وضعیت، یک واژه به کار ببریم

شناسه‌های وضعیت در کد انگلیسی هستند. متن فارسی باید همان معنی را برای کارمند روشن کند. جدول زیر برای بازبینی یکدستی واژه‌هاست و جای مقدارهای API را نمی‌گیرد.

| اصطلاح کد یا انگلیسی | عبارت پیشنهادی فارسی |
| --- | --- |
| Hold / held slot | رزرو موقت |
| Confirmed appointment | نوبت قطعی |
| `PENDING_PAYMENT` | در انتظار پرداخت |
| `PENDING_STAFF_APPROVAL` | در انتظار تأیید پذیرش |
| Unknown external outcome | نتیجهٔ نامعلوم سرویس بیرونی |
| Reconciliation | تطبیق نتیجه با مرجع |
| Callback task | وظیفهٔ تماس مجدد |
| Observed staff bridge | اتصال مشاهده‌شدهٔ بیمار به کارمند |

توضیح را برای خواننده ترجمه کنید، اما فرمان اجرایی و مقدار وضعیت ماشین‌خوان را دست‌نخورده نگه دارید. در تصویر یا پیام پشتیبانی، عبارت آشنای کارمند پذیرش معمولاً از ترجمهٔ تحت‌اللفظی ستون پایگاه بهتر است.

## ویرایش مستندات

- نسخهٔ انگلیسی و `.fa.md` را با هم تغییر دهید. دستور مشخص، مثال و راه برخورد با خطا بهتر از تکرار ادعای کلی دربارهٔ وضعیت است.
- شناسهٔ کد، دستور CLI و مسیر API را ترجمه نکنید؛ توضیح کاربرمحور را روان و طبیعی بنویسید.
- لاگ تولیدی، اسکرین‌شات موقت، گزارش قدیمی، راز و دادهٔ مشتری وارد مستندات Git نشود. شواهد را به اجرای دقیق CI ارجاع دهید.
- پیش از ارسال، `node --test scripts/check-docs.test.mjs`، `node scripts/check-docs.mjs` و `node scripts/check-versions.mjs` را اجرا کنید.

متن مجوز موجود در `docs/licenses/` با عبارت‌بندی اصلی نگهداری می‌شود؛ این متن راهنمای ویرایشی نیست که به‌دلخواه ترجمه شود.
