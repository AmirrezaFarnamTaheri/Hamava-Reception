# رابط وب مشترک هم‌آوا

[English](README.md) | [پروژه](../README.fa.md) | [راهنمای توسعه](../docs/development.fa.md)

برنامهٔ React/TypeScript/Vite محیط پذیرش راست‌به‌چپ فارسی و مسیرهای عمومی مراجعه‌کننده را فراهم می‌کند. این رابط به سرویس FastAPI در `/api/v1` وصل می‌شود و هرگز پس از خطای شبکه موفقیت ساختگی نشان نمی‌دهد.

## اجرای محلی

وقتی سرور در `http://127.0.0.1:8000` فعال است، در پوشهٔ `frontend/` اجرا کنید:

~~~sh
npm ci
npm run dev
~~~

برای ساخت بستهٔ ایستا `npm run typecheck` و `npm run build` را اجرا کنید. سرور در صورت وجود، فایل‌های `frontend/dist/` را ارائه می‌کند. آزمون‌های مرورگر باید از API نمایشیِ جداگانه استفاده کنند: بعد از ساخت، از ریشهٔ مخزن `python scripts/ci_ui.py test:ui test:workflows test:conversation test:privacy-notice` را اجرا کنید.

## ناوبری و محدودیت‌ها

امکانات کارکنان شامل امروز، نوبت‌ها، وظایف، تماس‌ها، مدیریت و کنترل‌های مجوزدار است. صفحهٔ عمومی `/talk/:slug` پیش از ایجاد نشست، رضایت پردازش می‌گیرد. پیوند `/respond/:id#secret` راز پاسخ را در حافظه نگه می‌دارد. ناوبری موبایل بر امروز/وظایف/تماس‌ها/بیشتر تأکید دارد. تنظیم اتصال پیش از بررسی سازگاری، اعتبارنامه نمی‌فرستد؛ اندروید از HTTPS استفاده می‌کند. مجوز و مرجع نوبت روی سرور می‌ماند. در نبود صوت یا RTC، متن کار می‌کند؛ رابط ادعای نوبت‌دهی آفلاین یا تأیید دستگاه واقعی ندارد.

قراردادهای نگهداری‌شده در [رفتار محصول](../docs/product.fa.md)، [معنای API](../docs/api.fa.md) و [بسته‌بندی بومی](../docs/clients-and-releases.fa.md) آمده‌اند.

## از کدام فایل شروع کنیم؟

| بخش | کد | قاعده‌ای که باید حفظ شود |
| --- | --- | --- |
| ورود و اتصال مرکز | `src/pages/Login.tsx`، `src/pages/Connection.tsx`، `src/platform.ts` | بررسی هویت سرور بدون اعتبارنامهٔ کارمند و الزام نشانی HTTPS مجاز |
| امروز و ناوبری | `src/App.tsx`، `src/pages/Overview.tsx` | نمایش اطلاعات مرکز جاری و ناوبری قابل‌دسترس موبایل |
| نوبت‌دهی | `src/pages/Appointments.tsx` | مدیریت انقضای رزرو، نسخهٔ قدیمی، شرایط بیعانه و نتیجهٔ نامعلوم |
| تماس و وظیفه | `src/pages/Calls.tsx`، `src/pages/TaskQueue.tsx` | تفکیک درخواست انتقال، اتصال واقعی و تماس مجدد با مسئول مشخص |
| گفت‌وگوی بیمار | `src/pages/Talk.tsx` | نمایش اطلاعیه قبل از نشست، روشن‌سازی تاریخ و تأیید تغییر |
| مالی و سیاست‌ها | `src/pages/Payments.tsx`، `src/pages/Costs.tsx`، `src/pages/PrivacyGovernance.tsx` | نمایش تسویهٔ معلق، بودجه، لغو رضایت و مجوز |
| ارتباط با سرور | `src/api.ts`، `src/hooks.ts`، `src/types.ts` | حفظ کد خطا، شناسهٔ درخواست، پاسخ نوع‌دار و وضعیت شکست |

## تغییر امن در رابط

برای افزودن یک اقدام نوبت، از درخواست و پاسخ واقعی API شروع کنید، نه شبیه‌سازی ثبت موفق در مرورگر. هنگام اجرای درخواست، حالت انتظار را نشان دهید، اقدام ناسازگار را غیرفعال کنید و در تعارض، نوبت مرجع را دوباره بگیرید. پس از قطع شبکه، راه تلاش دوباره یا ارجاع بدهید؛ موفقیت خیالی نسازید.

عرض ۳۲۰ و ۳۹۰ پیکسل و دسکتاپ، ترتیب حرکت Tab، بازگشت تمرکز بعد از پنجره، متن ترکیبی فارسی/لاتین، قلم درشت، فهرست خالی، پاسخ دیررس و خطای مجوز سرور را بررسی کنید. پنهان‌کردن گزینهٔ منو جای بررسی مجوز API را نمی‌گیرد.

پس از ساخت `frontend/dist/`، از ریشهٔ مخزن اجرا کنید:

~~~sh
npm --prefix frontend run test:browser-launch
python scripts/ci_ui.py test:ui test:workflows test:conversation test:privacy-notice --port 8137
~~~

CI اطلاع‌رسانی، فهرست انتظار/بیعانه، چرخهٔ RTC، برنامهٔ همراه و اتصال را هم می‌سنجد. هر مجموعهٔ مرورگر با سرور ساختگی جدا اجرا می‌شود و شواهد همان اجرا ذخیره می‌شوند، نه در کد.

## حالت بارگذاری و خطا را روشن نشان دهید

صفحه‌ای که درخواست تغییر می‌فرستد باید وضعیت خود درخواست را از وضعیت نوبت جدا نشان دهد. مثلاً بعد از کلیک روی «تأیید»، تا پایان HTTP ارسال دوباره را غیرفعال کنید. اگر درخواست موفق بود، همان وضعیت نوبت برگشتی را نمایش دهید. اگر تعارض نسخه رخ داد، نوبت فعلی را بگیرید و از کارمند بخواهید تغییر را مرور کند. اگر شبکه هنگام نوشتن تقویم بیرونی قطع شد، مسیر بررسی عملیات ذخیره‌شده و تطبیق نتیجه را نشان دهید.

برچسب درست از انیمیشن خوش‌بینانه مهم‌تر است:

| پاسخ یا وضعیت | نمایش پیشنهادی |
| --- | --- |
| جست‌وجوی زمان هنوز اجرا می‌شود | انتخاب قبلی باقی بماند و جست‌وجو «در حال بارگذاری» باشد |
| طبق قواعد خدمت زمان خالی وجود ندارد | نتیجهٔ خالی و امکان تغییر روز یا پزشک نشان داده شود |
| رزرو موقت منقضی شد | توضیح دهد زمان دیگر نگه داشته نشده و ظرفیت تازه بگیرد |
| نوبت در انتظار تأیید یا پرداخت است | گام باقی‌مانده را نشان دهد و برچسب «قطعی» نزند |
| کاربر مجوز ندارد | محدودیت را توضیح دهد، بدون نمایش جزئیات مرکز دیگر |
| اتصال قطع شد | فیلدهای ارسال‌نشدهٔ مجاز را حفظ کند و ادعای پذیرش سرور نکند |
| نتیجهٔ تقویم بیرونی نامعلوم است | راه مشخص بررسی همان عملیات قبلی را به کارکنان بدهد |

وقتی پنجره باز، بسته یا با خطا روبه‌رو می‌شود، تمرکز صفحه‌کلید و اعلام مناسب برای صفحه‌خوان را بررسی کنید. در چیدمان فارسی نام بلند، تاریخ شمسی، شناسهٔ لاتین و عدد را کنار هم آزمایش کنید. متن دوجهته گاهی نقص تراز را آشکار می‌کند که در نمونهٔ صرفاً انگلیسی دیده نمی‌شود.

## PR رابط باید چه اطلاعاتی داشته باشد؟

تغییر رابط بهتر است مسیر صفحه، نقش و محدودهٔ مرکز، درخواست API، حالت بارگذاری/خطا و یک آزمون مرورگر را مشخص کند. اگر قالب پاسخ API تغییر کرده است، `src/types.ts` و صفحهٔ مصرف‌کننده را با هم اصلاح کنید. اگر endpoint مجوز می‌خواهد، مطمئن شوید سرور حتی هنگام ورود دستی کاربر به مسیر، درخواست غیرمجاز را رد می‌کند.

اسکرین‌شات برای بررسی تغییر ظاهری مفید است، اما تصویرهای موقت را کنار خروجی همان CI یا بررسی نگه دارید. تصویر ساخته‌شده و لاگ مرورگر نباید وارد درخت کد نگهداری‌شده شوند.

## مرز برنامهٔ بومی

همین رابط با Electron و Capacitor بسته‌بندی می‌شود. میزبان بومی فقط پل مجاز اتصال، نگهداری نشست و قابلیت دستگاه را فراهم می‌کند. `src/platform.ts` پیش از ورود، `/api/v1/client-info` را بررسی می‌کند و اجازهٔ ایجاد پایگاه آفلاین دومِ نوبت‌ها را نمی‌دهد. پس از خروج، اعتبارنامه نباید بی‌خبر از مخزن قبلی بازگردد. [برنامه‌های همراه و انتشار](../docs/clients-and-releases.fa.md) را ببینید.
