# هم‌آوا

**میز پذیرش فارسی برای نوبت‌ها، تماس‌ها و پیگیری‌ها.** [English](README.md)

هم‌آوا کارهای روزمرهٔ پذیرش را در یک محیط جمع می‌کند: تقویم نوبت‌ها، گفت‌وگوی مراجعه‌کننده، وظایف کارکنان، پیام‌رسانی، بیعانه و راه روشن برای ارجاع به انسان وقتی یک درخواست با خودکارسازی به نتیجه نمی‌رسد. محیط وب، برنامهٔ ویندوز و همراه اندروید به یک سرور متصل می‌شوند و به اطلاعات یکسان مرکز دسترسی دارند.

نسخهٔ فعلی کد **0.2.2** است. می‌توانید نمونهٔ کامل متنی را روی رایانهٔ خود اجرا کنید. گفتار، تلفن، تقویم‌های بیرونی، پیامک و پرداخت اتصال‌های جداگانه‌اند و هر مرکز تنها بعد از تنظیم و آزمودن آن‌ها را فعال می‌کند. این مخزن کد و روش ساخت برنامه را فراهم می‌کند؛ سرویس پذیرش واقعی و ازپیش‌راه‌اندازی‌شده نیست.

## اجرای نمونهٔ هم‌آوا

به Python **3.12**، ‏Node.js **24** و npm نیاز دارید. این دستورها برای پوستهٔ POSIX هستند و از ریشهٔ مخزن اجرا می‌شوند:

~~~sh
python3.12 -m venv .venv
. .venv/bin/activate
python -m pip install --upgrade -r requirements-bootstrap.txt
python -m pip install -c requirements.lock.txt '.[test,media]'
npm --prefix frontend ci
npm --prefix frontend run build
cp .env.example .env
set -a; . ./.env; set +a
python -m uvicorn receptionist.main:app --host 127.0.0.1 --port 8000 --no-access-log
~~~

نشانی **http://127.0.0.1:8000** را باز کنید. حساب مالک نمایشی `owner@example.test` و گذرواژهٔ آن `DemoReception2026!` است. صفحهٔ گفت‌وگوی مراجعه‌کننده نیز در **http://127.0.0.1:8000/talk/bahar** قرار دارد. مراکز، افراد، نوبت‌ها و پاسخ‌های پیام/پرداخت این محیط ساختگی هستند تا بدون اتصال سرویس واقعی بتوانید کار را تجربه کنید.

در پنجرهٔ دیگری همان محیط پایتون و فایل `.env` را بارگذاری و کارگر پس‌زمینه را اجرا کنید:

~~~sh
python -m receptionist.worker
~~~

وقتی کارگر جداگانه اجرا می‌شود، مقدار `RUN_WORKER=false` در فرایند API باقی بماند. در ویندوز از دستورهای متناظرِ فعال‌سازی محیط مجازی و بارگذاری متغیرها استفاده کنید. پایگاه دادهٔ عملیاتی PostgreSQL **16** است و نمونهٔ محلی از SQLite استفاده می‌کند. بعضی آزمون‌های پردازش صوت به FFmpeg نیاز دارند.

### اولین گردش در برنامه

1. وارد شوید و میان دو مرکز ساختگی **بهار** و **نیلوفر** جابه‌جا شوید. مرکز انتخاب‌شده تعیین می‌کند کدام نوبت، تنظیم و وظیفه دیده شود.
2. در تقویم، پزشک و خدمت را انتخاب کنید، زمان آزاد را ببینید، رزرو موقت بگیرید و سپس نوبت را تأیید کنید. رزرو موقت منقضی می‌شود و نوبت قطعی نیست.
3. نوبت را جابه‌جا یا لغو کنید. هم‌آوا نسخهٔ فعلی آن را بررسی و تغییر را ثبت می‌کند؛ تغییر همکار دیگری نباید بی‌خبر بازنویسی شود.
4. صف وظایف کارکنان را باز کنید و درخواست ارجاع یا پیامِ تعیین‌تکلیف‌نشده را ببینید. درخواست «در انتظار» تا رسیدن شاهد مرحلهٔ بعد، در انتظار می‌ماند.
5. در صفحهٔ مراجعه‌کننده، رضایت پردازش را پس از خواندن اطلاعیه ثبت کنید و به فارسی نوبت بخواهید. تاریخ مبهم یا اصلاح یک اطلاعات را امتحان کنید و پرسش روشن‌کنندهٔ برنامه را ببینید.

## از کدام مسیر ادامه دهیم؟

نمونهٔ نمایشی وقتی مفیدتر است که یک درخواست را تا آخر دنبال کنید. ابتدا برای بیمار ساختگی نوبت ثبت کنید، بعد تغییری انجام دهید که صفحهٔ قبلی را قدیمی کند. تعارضی که می‌بینید عمدی است: دو کارمند نباید بتوانند بدون دیدن تغییر همدیگر، یک نوبت را بازنویسی کنند.

اگر با کار مشخصی سراغ هم‌آوا آمده‌اید، از این راهنما شروع کنید:

| کار شما | راهنمای اول | چه چیزی را بررسی کنید؟ |
| --- | --- | --- |
| پذیرش یا مدیر مرکز | [راهنمای محصول](docs/product.fa.md) | وضعیت نوبت، ارجاع به کارکنان و روز کاری |
| توسعه‌دهنده | [راهنمای توسعه](docs/development.fa.md) | نقشهٔ کد، آزمون تکرارپذیر و تغییر امن پایگاه |
| سازندهٔ برنامه یا اتصال | [راهنمای API](docs/api.fa.md) | محدودهٔ دسترسی، فیلدها، کلید تکرار و خطاها |
| مسئول سرور | [راهنمای استقرار](docs/deployment.fa.md) | تنظیمات، سلامت، شروع کارگر و تمرین بازیابی |
| مسئول انتشار | [انتشار برنامه‌های همراه](docs/clients-and-releases.fa.md) | بستهٔ ویندوز/اندروید، امضا و آزمون دستگاه |
| پژوهشگر | [راهنمای پژوهش](docs/research.fa.md) | حقوق داده، ارزیابی گفتار، ظرفیت و سنجش پایلوت |

داده‌ها و پاسخ‌های تأمین‌کننده در این نمونه ساختگی‌اند. با آن‌ها می‌توان رفتار رابط و سرور را آزمایش کرد، اما رفتار اپراتور تلفن، پذیرندهٔ پرداخت یا مرکز واقعی را ثابت نمی‌کنند. [عملیات](docs/operations.fa.md) بررسی‌های لازم برای این اتصال‌ها را توضیح می‌دهد.

## اجزای پروژه

| بخش | وظیفه | محل کد |
| --- | --- | --- |
| سرور پذیرش | نوبت‌دهی، هویت، مجوزها، سیاست مرکز و وضعیت نهایی کار | `backend/receptionist/` |
| کارگر پس‌زمینه | یادآوری، ارسال، تطبیق نتیجه و پیگیری عملیات | `backend/receptionist/worker.py` |
| رابط مشترک | میز پذیرش راست‌به‌چپ، مدیریت و گفت‌وگوی عمومی | `frontend/` |
| برنامهٔ دسکتاپ | میزبان Electron، اتصال مرکز و نگهداری امن نشست | `apps/desktop/` |
| برنامهٔ اندروید | میزبان Capacitor، اتصال HTTPS و نشست حفاظت‌شده در دستگاه | `apps/mobile/` |
| گفتار و رسانه | گفتار محلی، AudioSocket، ‏LiveKit و انتقال Asterisk به‌صورت اختیاری | `services/local_speech/`، `backend/receptionist/media/`، `deploy/asterisk/` |
| زیرساخت | Docker، ‏Caddy، پایگاه، پایش و CI | `compose.yaml`، `deploy/`، `.github/workflows/` |

ثبت قطعی نوبت، مجوز ارتباط و صف پیام در اختیار سرور است؛ برنامه‌های همراه تقویم مستقل نیستند. پذیرش درخواست توسط سرویس بیرونی لزوماً به معنی ثبت نوبت، تحویل پیامک، تسویهٔ پول یا اتصال کارمند نیست. این تفاوت در وضعیت‌های برنامه و رکوردهای آن حفظ می‌شود.

## اجرای آزمون‌ها

بعد از نصب وابستگی‌های بالا:

~~~sh
python -m ruff check backend scripts services
python -m pytest -q
python scripts/protocol_conformance.py --output artifacts/backend/protocol-conformance.json
npm --prefix frontend run build
npm --prefix frontend run test:browser-launch
npm --prefix apps/desktop test
node scripts/check-versions.mjs
node --test scripts/check-docs.test.mjs
node scripts/check-docs.mjs
~~~

گردش‌کار `.github/workflows/verify.yml` علاوه بر این‌ها، پایگاه PostgreSQL آزمایشی، مسیرهای مرورگر و کانتینر قابل‌استقرار را بررسی می‌کند. ساخت بومی ویندوز و اندروید هم مراحل جداگانه دارد. نتیجهٔ هر نسخه را از اجرای Actions همان commit بخوانید، نه گزارش قدیمی.

## ادامهٔ مسیر

[فهرست مستندات](docs/README.fa.md) وظیفهٔ هر راهنما را مشخص کرده است. برای اولین استقرار، [استقرار](docs/deployment.fa.md) و سپس [عملیات](docs/operations.fa.md) را بخوانید. برای شناخت نوبت‌دهی و اتصال‌ها به [معماری](docs/architecture.fa.md) و [API](docs/api.fa.md) مراجعه کنید. توسعه‌دهندگان از [توسعه](docs/development.fa.md) و مسئولان ساخت برنامهٔ بومی از [برنامه‌های همراه و انتشار](docs/clients-and-releases.fa.md) استفاده کنند.

**پیش از پذیرش مراجعه‌کنندهٔ واقعی** باید تنظیمات اختصاصی تولید، پشتیبان آزموده‌شده، مسیر پاسخ‌گویی کارکنان و حساب‌ها و مجوزهای واقعی سرویس‌های فعال فراهم شود. [فهرست راه‌اندازی](docs/operations.fa.md) روشن می‌کند کدام آزمون را نرم‌افزار انجام می‌دهد و کدام تأیید بر عهدهٔ مرکز و تأمین‌کنندگان است.
